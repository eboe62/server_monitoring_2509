# Request Analysis Template

## Context

Provide the relevant project context.

Examples:

* affected service
* affected component
* ADR references
* operational constraints
* current implementation

---

## Objective

Describe the objective.

What problem must be solved?

What decision must be made?

---

## Scope

Define exactly what is in scope.

Define exactly what is out of scope.

---

## Constraints

List all applicable constraints.

Examples:

* no architecture redesign
* no downtime
* upstream compatibility required
* no new dependencies
* Docker Compose only

---

## Available Evidence

Provide available evidence.

Examples:

* logs
* metrics
* command outputs
* configuration
* runtime inspection

---

## Required Analysis

The analysis must include:

1. Current State
2. Findings
3. Risks
4. Options
5. Recommendation
6. Validation Plan

---

## Prohibited Actions

Do not:

* implement changes
* generate code
* modify architecture
* assume runtime behaviour

unless explicitly requested.

---

## Expected Deliverable

Provide:

* structured analysis
* identified risks
* recommended option
* validation requirements
